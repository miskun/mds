# MDS Source Hygiene

Use this skill before commits, reviews, or documentation updates when source comments or written project guidance may have been generated by AI.

## Goal

Keep source text useful, local to MDS, and free of planning-room prose.

## Review Rules

- Keep code comments rare and practical.
- Prefer comments that explain public contracts, accessibility constraints, browser quirks, or non-obvious implementation details.
- Remove comments that narrate obvious code, implementation history, personal reasoning, internal debate, or rejected alternatives.
- Avoid references to unrelated projects, inspiration sources, AI tools, or prior conversations.
- Do not encode temporary planning language into source comments.
- Keep documentation direct: state what the project supports and how to use it.

## Sweep

Search for comments and likely prose drift:

```sh
rg -n "//|/\\*|TODO|FIXME|because|in order to|AI|Codex|ChatGPT|inspired by|similar to|decision|reasoning" src .storybook AGENTS.md README.md
```

Inspect matches manually. Some matches are valid, especially TypeScript directives, Storybook globs, and concise project guidance.

## Edit Standard

When a comment is needed, make it shorter than the code it clarifies whenever possible.

Good:

```ts
// Strip native titles so only the MDS tooltip is shown.
```

Avoid:

```ts
// We decided to strip this because earlier testing showed that browsers also render
// native tooltips and this conflicted with the custom tooltip strategy discussed above.
```
